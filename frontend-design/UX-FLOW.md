# 核心应用链 UX 优化 · 上传 → 等待 → 报告

> 依据：真实后端链路（`POST /api/v1/report` → `app/pipelines.py` 全链路编排）与
> 现有极简 ZINE 前端系统。目标：让流程**更顺畅、可信、低焦虑**。

---

## 1. 现状梳理（用户可见的链路）

**后端真实流水线**（与界面一一对应）：

```
上传影像+参数 → 载入/校验 → 影像质量校验(IQI/黑度) → 预处理
→ 缺陷检测 → 当量量化 → 标准评级(NB/T47013.2) → 落库 → 生成 PDF/A 报告
```

**现有界面缺口（用户视角）**：

| 阶段 | 用户痛点 | 后果 |
|------|----------|------|
| 上传前 | 不知道支持哪些格式、对底片有什么要求；`像素标定/母材厚度`参数含义不清、为何必填 | 传错格式/漏填参数，到提交才报错；对专业参数产生陌生感与不信任 |
| 上传中 | 拖入后无即时校验、无预览、无格式错误原因 | 反复试错，体验挫败 |
| 等待 | 只有"加载中…"；不知道进行到哪一步、要多久；长时间无反馈 | 焦虑、怀疑卡死，频繁重试 |
| 报告 | 信息平铺无解读；看不懂"II 级"意味着什么、下一步该做什么；"需复核"无解释 | 拿到报告不知如何行动，误判风险 |

## 2. 优化后的完整旅程（三阶段 + 引导/兜底）

```
┌─────────┐   ┌─────────┐   ┌──────────┐   ┌──────────────┐
│ 0 准备    │ → │ 1 上传    │ → │ 2 处理中   │ → │ 3 报告解读     │
│ 三步引导  │   │ 校验+预览 │   │ 阶段进度   │   ├─ 成功 → 操作建议
│ 格式说明  │   │ 参数解释  │   │ 计时/状态  │   ├─ 需复核 → 原因+升级
└─────────┘   └─────────┘   └──────────┘   └─ 失败 → 原因+可行动项
```

### 阶段 0–1：上传前的引导与格式说明（补）
- **三步引导**：① 准备底片 → ② 填写参数 → ③ 查看报告。
- **格式与规格说明**：支持 DICOM(.dcm) / PNG / TIFF；建议 ≥500×500、8/16bit 灰度；
  提示"若底片缺 IQI 或黑度不足，将标记为不可评片（系统保守原则）"。
- **参数行内帮助**：`像素标定(mm/px)` 给默认值 `0.1` 与解释；`母材厚度 T(mm)` 必填（评级依据），
  缺省时明确"评级将被锁定，仅出图谱"。
- **即时校验**：拖入文件后立刻校验 格式/大小/可读性，错误给出**具体原因与修正建议**
  （如"PNG 不支持 32 位彩色，请导出为 8/16 位灰度"）。
- **预览**：缩略图 + 影像规格（尺寸/位深），确认无误再提交。

### 阶段 2：等待时的进度反馈与状态提示（补）
- **真实流水线阶段进度**：用后端同名子任务作步骤，而非笼统"加载中"：
  载入影像 → 质量校验(IQI/黑度) → 缺陷检测 → 当量量化 → 标准评级 → 生成报告。
  每步有独立状态（待执行 / 进行中 / 完成 / 失败）。
- **计时与预期**：实时计时 + "通常 15–30 秒"；超时给出提示而非无限等待。
- **可离开提示**："处理完成后自动归档，可在『档案检索』随时查看"——允许用户离开，降低等待焦虑。
- **失败状态**：明确失败子任务与原因，给出可行动项（调整参数重试 / 更换底片 / 转人工复核），
  绝不静默失败或只给笼统错误码。

### 阶段 3：报告生成后的结果解读与操作建议（补）
- **结论先行**：顶部直接给出 综合级别 + 一句话结论（如"II 级，可接受；含 2 处小缺陷"）。
- **需复核明示**：`need_review` 时用醒目横幅说明**为什么**（标准数值未授权 / 影像质量不达标 /
  分歧待仲裁），并引导"发起人工复核"——强调这是保守原则，不是误报。
- **结果解读**：缺陷清单用当量尺寸 + 对应限值对照（如"条形限值 II ≤ T/3=6.7mm，实测 4.1mm ✓"）。
- **操作建议**（与后端能力一一对应）：
  - 导出 PDF/A 报告（归档合规）→ 已有 `report` 端点；
  - 发起人工复核 / 仲裁 → 已有 M7 复核闭环；
  - 查看同工件历史 → 已有 `records` 检索统计。
- **签字与免责**：保留签署位与免责声明，明确"仅供质量追溯参考"。

## 3. 信任与低焦虑设计原则

1. **真实阶段名**：进度条对应真实子任务，用户能预判"卡在哪、还剩什么"。
2. **预期管理**：给出典型耗时与实时计时，超时兜底提示。
3. **可并行**：允许离开，结果自动归档，回来即见。
4. **失败可行动**：错误必带"原因 + 下一步"，不抛黑盒。
5. **保守即可信**：需复核场景先给结论再给理由，且明确"宁保守不误放行"。
6. **本地优先**：全程提示"本地处理、影像不外传"，降低数据安全顾虑。

## 4. 状态矩阵（界面反馈一览）

| 状态 | 触发 | 界面反馈 |
|------|------|----------|
| 待上传 | 初始 | 引导 + 格式说明 + 示例 |
| 校验失败 | 格式/大小/可读性不合规 | 行内错误：原因 + 修正建议，禁止提交 |
| 参数缺失 | 厚度未填 | 字段级提示：评级将锁定的后果 |
| 处理中 | 提交后 | 阶段进度 + 计时 + 预计 + 可离开提示 |
| 处理失败 | 流水线任一步失败 | 失败阶段标红 + 原因 + 重试/调整/转人工 |
| 成功 | 评级完成 | 结论先行 + 缺陷解读 + 操作建议 |
| 需复核 | need_review=true | 醒目标记 + 原因 + 发起复核入口 |
