# 优化落地 P2 设计（长线方向 · 不排期实施）

> 状态：**设计文档，未实施**。P2 各项均需 GPU 训练 / 外部模型 / 多方数据，成本与周期远超
> P0/P1，故仅输出设计蓝图供后续立项，不进入当前迭代。
> 依据：已核实代码锚点（`yolo_detector.py` / `nb47013.py` / `grade/registry.py` /
> `default.yaml` / `training/` 目录），所有设计均锚定现有模块与契约。

---

## 1. CNN+Transformer 检测主干（借鉴 MFE-IDD / Yolo-MSAPF）

**目标**：提升罕见类（裂纹/未熔合）召回与多尺度小目标（气孔）精度。

**设计**：
- **训练侧**（`backend/training/`，新增 `custom_yolo.yaml` + 训练脚本）：
  - backbone 保持轻量 CNN（YOLOv8n 级别）以保住 CPU 推理可行性；
  - neck 引入**多尺度对齐融合（MSA）+ 并行特征滤波（PF）**（Yolo-MSAPF 思想），
    替换默认 PAN-FPN 的拼接层；
  - 可选：在 P3 层引入轻量 Transformer 编码（MFE-IDD 的 CNN+Transformer 混合），
    用全局上下文补局部纹理的不足——**只在 GPU 训练可行后立项**（当前 CPU-only 80 epoch
    已极慢，Transformer 训练不可承受）。
- **推理侧**（`backend/domain/detect/yolo_detector.py`）：P1-A 已提供 `infer_tta`；
  P2 若换主干，ONNX 导出须复用现有 legacy 导出（monkeypatch `dynamo=False`）+ 通道优先布局
  自适应 + sigmoid 启发式（这些已固化，换主干不破坏）。
- **验收**：以 Golden Set 复测 mAP50 / 罕见类召回；对比 `real_synth2/best.pt` 基线。

**约束**：训练数据量不足前（<500 真实片）换主干收益有限——**先完成 P0-B 数据扩充再立项**。

---

## 2. 像素级分割定级（借鉴 WPFormer，CVPR'25）

**目标**：从 bbox 定级升级为像素级测量（NB/T47013 定量评级的硬需求：面积/长径/点数）。

**设计**：
- 现 `mask_refine`（`backend/domain/quantify.py`）已做包围盒内自适应阈值掩膜，作**快速回退**；
- P2 新增**分割头**（轻量，如 DeepLabv3-MobileNetV3 或 STDC）：
  - 输入：bbox ROI（从检测器裁剪）；
  - 输出：缺陷像素掩膜 → 精确 `length_mm/area_mm2`，直接喂 `Nb47013Grader._grade_round`
    （点数按面积换长径）与 `_near_critical`（临界判定更准）；
  - 数据：训练集需补像素级标注（Label Studio 多边形标注，P0-G 闭环顺带积累）；
- **契约**：`Detection.mask_ref` 字段已预留，`Quantifier.measure` 协议不变。

**周期**：3-4 周（标注 + 训练 + 评估），排 P2 中期。

## 3. VLM 评片报告（借鉴 MMAD，ICLR'25）

**目标**：自动生成可解释评片意见与处置建议文本，提升报告价值与产品差异化。

**设计**：
- **输入**：底片图 + 检测结果（bbox/类别/置信/不确定）+ 评级结果（GradeResult）；
- **实现**：本地 VLM（Ollama qwen2.5-vl 或 DeepSeek-VL2）经 `backend/app/routers/explain.py`
  已有解释端点扩展（新增 `POST /explain/vlm`，独立适配器，不污染判定主干）；
- **输出**：结构化评片意见 JSON（缺陷描述 / 级别解读 / 处置建议 / 复核要点），
  由 `backend/infra/reporting/pdf_reporter.py` 渲染进报告；
- **红线**：VLM 文本**仅作辅助解释，不参与评级**；评级必须走 `Nb47013Grader`。
  VLM 输出前强制叠加 `disclaimer_for(tables)` 免责声明。

**周期**：2-3 周（模型选型 + 提示词 + 报告接入），排 P2 后期。

---

## 4. 联邦 / 边缘部署（借鉴 FedML / FATE）

**目标**：多厂区/多客户数据不出厂，各自本地训练、仅聚合梯度（NDT 底片常涉商业机密）。

**设计**：
- **现状**：`backend/infra/sync.py` 已有 `Syncer` 协议（`push/pull/federate`），
  `default.yaml` 有 `sync.kind: local|http` 占位——P2 只需替换适配器实现；
- **实施**：
  - 服务器：FedML 或 FATE 的聚合服务（独立进程/容器，不在桌面端内嵌）；
  - 客户端：`HttpSyncAdapter` + 本地训练任务（复用 `real_finetune.py`），
    仅上传模型梯度/权重，底片与标注**永不外发**；
  - 安全：TLS + 令牌（`sync.http_token` 已预留），联邦聚合需人工审计；
- **硬前置**：客户数据授权边界确认（生产合规），否则不立项。

**周期**：4-6 周，排 P2 后期 / v3。

## 5. 各方向依赖关系与立项门槛

| 方向 | 前置依赖 | 立项门槛 |
|---|---|---|
| CNN+Transformer 主干 | P0-B 数据量（≥500 真实片）+ GPU 训练环境 | mAP50 基线已冻结、数据量达标 |
| 像素级分割 | P0-G 标注闭环积累多边形标注 | 分割标注 ≥200 张 |
| VLM 评片报告 | 本地 VLM 可用（Ollama 已装） | 报告字段稳定后 |
| 联邦/边缘 | 客户授权 + 多站点参与 | 至少 2 站点试点 |

**共同原则**：所有 P2 改动遵守 §19 架构护栏与双轨纪律（竞赛/合规逻辑独立适配器、
不污染 `domain/grade` 主干）；评级主干保持「模型独立判定 + 人工复核兜底」。
