新模型在 **val 集 mAP50=98.6% / recall 97.5%**（val 由 steel 合成 + 程序合成 + 少量真实构成），
但真实底片检出几乎归零——典型的**合成域过拟合 / 真实域漂移**。

## 根因分析

训练集 `data/training/data.yaml`（train 3422）构成：
- **steel 2699 张（79%）**——外部合成/仿真底片，与真实 DR 底片风格差异大；
- 程序合成 450 张（13%）；
- **真实 user 仅 128 张（3.7%）+ 伪标签 11 张**——真实域信号被合成域淹没。

模型学到的是"合成域统计"，对真实底片的灰度/纹理分布不置信 → 检出塌缩。
与历史教训一致（2026-08 记录：合成占比失衡的 real_rare 重训在真实片退化，real_synth2 因配比合理才胜出）。

## 处置（已完成）

2. **已回滚**：运行时 + `_pkg/ScanDetection/{models,backend/models}/weights/best.onnx` 恢复旧模型
   （md5 `f4be8cfe`，复验真实集 67 框，与基线一致）——产品保持可用；
3. 新模型权重保留在 `runs/gpu/auto_v1_20260815_185551/weights/best.pt`（不删除，供配比实验）。

## 教训（铁律级）

- **合成域占比过高必然真实域漂移**：真实 user 信号被淹没时，val 指标（合成域）再高也不可信；
  **部署门槛 = 真实底片检出回归 >0 框**（`deploy_model.py` 已强制），本次正是它拦住了坏模型；
- 训练数据配比策略：steel 等外部合成源**必须限流/降采样**（建议 ≤ 真实标注量级的 2-4 倍，
  或按真实:合成 ≈ 1:3 封顶），不能无差别全量灌入。

## 后续重训建议（A/B 方案）

- **A（推荐）**：steel 限流（随机抽 ≤500 张）+ 真实 user 128 + 伪标签 11 + 程序合成减半（225）
  → 重训 100 epoch；`dataset_builder` 需支持按源限流（后续增量）；
- **B**：以 `real_synth2/best.pt` 权重为预训练，微调上述配比数据（保留已验证的真实域先验）；
- 验收一律走 `deploy_model.py` 真实集回归 + Golden Set，不再以合成 val 指标为准。
