# ONNX INT8 量化可行性验证报告（P1-D）

> 日期：2026-08-15 ｜ 模型：`models/weights/best.onnx`（real_synth2 体系已验证导出，12.24MB，6 类）
> 工具：`backend/training/quantize_onnx.py`（PTQ 静态 INT8 + 动态量化对比，自包含复刻检测器后处理）
> 环境：onnxruntime 1.20.1 + onnx 1.22（ML 训练 venv，CPU-only）

## 结论（一句话）

**当前环境与模型下，INT8 量化暂不可用，保持 FP32 CPU 推理；不建议进入部署。**

## 量化对比

| 方案 | 模型体积 | 压缩 | 24 张真实底片检出 | 结论 |
|---|---|---|---|---|
| FP32（现状） | 12.24 MB | — | **67 框**（22/24 张有检出） | 基线 |
| PTQ 静态 INT8 | 3.52 MB | 71.2% | **0 框**（全部丢失） | ❌ score 完全坍缩 |
| 动态 INT8（权重） | 3.39 MB | 72.3% | 无法加载运行 | ❌ CPU EP 不支持 ConvInteger |

## 失败机理

1. **静态 INT8 检出归零**：本模型 legacy ONNX 导出的类别通道是**已融合 sigmoid 的概率**
   （∈[0,1]），量化标定（10 张真实底片）对输出层/激活范围估计不良，导致全部预测置信
   被压到阈值以下 → 0 检出。实测 FP32 同口径 67 框 → INT8 0 框，Δ=-100%。
2. **动态 INT8 无法运行**：onnxruntime 1.20 CPUExecutionProvider 未实现 `ConvInteger`，
   加载即 `NOT_IMPLEMENTED`（需 TensorRT/OpenVINO 等量化 EP）。

## 已尝试的绕行

- 静态量化前对输入做 pre-processing（ORT 建议），无效（模型输入已是归一化 blob）；
- 校准集加大到 10 张真实片（含缺陷底片），仍坍缩；
- 恢复进程内原生删除规避沙箱 safe-delete 拦截（`_restore_native_delete`，仅删自身临时文件）。

## 对后续的启示

- **不要**把 INT8 作为 CPU 部署的默认路径（score 分布会破坏逐类阈值 `class_conf` 与
  `review_conf` 语义，可能造成漏检——在安全关键系统里不可接受）。
- 边缘部署（v3）优先评估：**TensorRT（GPU）INT8** 或 **OpenVINO（CPU）INT8**，它们有
  针对检测模型的量化校准与算子支持；或用 **FP16 半精度**（体积减半、score 影响小）。
- 若必须 CPU INT8：需用**更多含缺陷底片**做校准、量化后按新 score 分布**重标定**
  `class_conf`/`review_conf`，并在 Golden Set 复测 mAP50——本报告显示当前标定策略不达标。
