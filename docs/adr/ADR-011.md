## 背景

1. **新模型**：Marigold V2（arXiv 2609.08084，SIGGRAPH Asia 2026 / ACM TOG，华为 Bayer Lab
   苏黎世 + EPFL + 博洛尼亚大学）把阿里通义 **Qwen-Image-Edit-2509（28.85B DiT 图像编辑模型）**
   经 **4-bit QLoRA（rank 128）+ 单步推理**改造为**单目深度估计器**。两项关键创新：
   - **iREPA-depth**：把 DiT 中间表征对齐到"由**真值深度**提取的 DINOv3 语义特征"（非 RGB）；
   - **SinkLoss**：把图切成 5×5 小块，块内用 Sinkhorn 最优传输做**软的一对一指派**——只要求
     块内"预测值集合 ≈ 真值集合"（**允许置换**），不强制逐像素对位，专治含噪真值下的飞点。
   训练仅 74K 图、单张 32GB 卡、一周内完成；零样本深度在 KITTI/ETH3D 较此前最优改善 16–26%；
   代码与权重 Apache 2.0（`github.com/huawei-bayerlab/marigold-v2`）。

2. **本系统任务**：射线底片（DICOM/CR/DR，单通道衰减图）的 **2D 缺陷检测/分类/量化/标准判定**
   （§1.3 六类缺陷，NB/T47013.2-2015）。**任务与模态均与单目深度估计不一致**。

3. **问题**：该模型能否"拿来优化整个软件"？直接拿权重显然不行——需要逐组件判定"能借的本质
   是什么、落在哪个模块"。本 ADR 固化这份映射与采纳决策。

## 决策

### A. 采纳：Sinkhorn 软匹配损失（`backend/training/losses.py`）

- 提供纯 numpy 的 `sinkhorn_log` / `sinkhorn_transport_cost` / `tile_sinkhorn_loss`，以及
  可反传的 torch 懒加载版 `torch_sinkhorn_cost`（CI 无 ML 环境不受影响）。
- **解决的真实问题**：本系统监督信号含结构性噪声——(1) X 光缺陷边界半透明/模糊，评片员轮廓
  不重合；(2) 稀有类（裂纹/未熔合/未焊透）样本极少、预标注定位精度有限；(3) 逐像素 L1/L2 会
  逼模型复现噪声、产生飞点、伤边缘。SinkLoss 只约束块内**值的集合**（置换不变），对位置抖动
  不敏感。
- **可插拔**：不改动既有训练入口 `backend/models/train.py` 与检测/量化主干（§19.4）；作为
  可选用损失，在训练掩膜头 / 缺陷密度图辅助任务 / 伪标签再训练时接入。
- **验证**：`backend/tests/test_sinkhorn_loss.py`（13 项：置换不变性、对照 MSE、自匹配最小、
  eps 单调、掩膜剔除、数值稳定、批量前导维度、梯度可反传、入参校验、torch↔numpy 一致）。

### B. 采纳：形状保真评测指标（`harness.shape_fidelity_metrics`）

- 对同类别、IoU≥阈值的匹配对，量化解耦的三类误差：`center_err`（定位）、`scale_err`（尺度）、
  `aspect_err`（长宽比）。
- **动机（受 SEE 启发：聚合误差掩盖边界质量）**：mAP@0.5 只要求 IoU≥阈值，"框盖住缺陷、但
  长宽比错"仍计 TP；而 §5.4 按 `aspect_ratio=L/W`（≤3 圆形 / >3 条形）归类、§6.2 据此评级，
  形状误差**直接改变评级结论**（细长裂纹尤甚）。该指标把这些误差从聚合指标里"救"出来。
- **只做加法**：不改动 `detection_metrics` / `pod_curve` / `check_regression` 的既有行为，
  不改变回归门禁口径（避免历史基线失效）。
- **验证**：`backend/tests/test_shape_fidelity.py`（9 项：完美→0、三类误差解耦、阈值/类别
  不匹配、一对一占用、多缺陷取均值）。

### B2. 采纳：形状保真接入 Golden 评估闭环（`backend/evaluation/run_eval.py`）

- `run_golden_evaluation` 逐图计算形状保真，按**匹配对数加权**聚合（不能用图均值——只有 1 对
  匹配的图会被与 20 对的图等权，实测该口径差异可达数倍）。
- 落到三处：评估报告 `shape_fidelity` 字段（models API 的 `metric_map` 数据源）、返回摘要、
  实验追踪的 `shape_*` 标量；模型卡 `metrics` 内嵌 `shape_fidelity`，并追加一条局限说明
  （**"mAP 高不代表形状可信"**）。
- **仍不进回归门禁**：`metrics` 顶层结构与 `check_regression` 未动，历史 `baseline.json` 有效。
- **实证**：新测试 `backend/tests/test_shape_fidelity_closed_loop.py`（7 项）里有一项直接演示盲区
  ——构造一个"中心基本对齐、长宽比被压扁但仍满足 IoU≥0.5"的预测，**mAP@0.5 报 1.0 满分，而
  `aspect_err` 报 0.4595**。这是该指标存在意义的可执行证明，而非口头论证。

### C. 推迟：X 光/医学影像域基座 + 薄适配器（**调研已完成**）

调研 memo：`docs/research/xray-foundation-models.md`。核心结论：

1. **不存在公开的"焊缝 RT 域"基座**。最对口的 WRT-SAM（arXiv 2502.11338，**中国特种设备检测
   研究院**——本项目应用场景的同体系机构）**未发现开源 checkpoint**；焊缝 RT 自监督方向有代码
   仓库（`github.com/longteng-coder/Wdsf-ssl`）但用自建数据。
2. **朴素用 SAM 在焊缝 RT 上失败**（被 WRT-SAM 的消融钉死）：原版 SAM "Everything" 模式在
   GDXray 焊缝图上 **IoU 仅 1.13**；加 Adapter 后升到 49.25，再加频域/多尺度 Prompt 到 51.36。
   即 **"通用分割基座直接拿来用"这条路有反例**。另有独立评测显示 SAM 在带钢/瓷砖/钢轨等
   工业表面缺陷上同样表现不佳。
3. **传统 U-Net 在 IoU 上仍能打赢 SAM 系**（GDXray 焊缝：66.72 vs 51.36）。**换基座不是免费
   升级，部分指标会倒退。**
4. **许可证是硬阻塞**：RAD-DINO（最接近"灰度透射 X 光"的公开基座）许可证**存在冲突**——
   Microsoft 官方目录标注 **MSRLA / 仅限研究**，部分第三方镜像标注 **MIT**。本项目涉及承压设备
   检测交付，商用前**必须核对原始许可文件**，不能采信二手标注。
5. **真正值得偷的是配方不是基座**：WRT-SAM 的 **FPG 频域 Prompt（2D DCT 通道分组）**解决的正是
   "灰度图缺乏颜色/纹理线索"这一本项目同样面对的问题，且是**即插即用的通道注意力模块**，
   不依赖任何基座。

**前置任务（已交付）**：调研 memo + 三条下一步路径（①频域 Prompt 移植 → ②用 RAD-DINO 冻结特征
做线性探测，作为决定性的负向筛子 → ③仅在②为正时考虑"冻结骨干 + 薄适配头"）。
**在②的结果出来前，不动骨干。**

### D. 推迟：QLoRA DiT 稀有类合成

- §5.6 已规划"受控生成/扩散"扩样；Marigold V2 给出了**低成本配方**（QLoRA DiT 单卡微调）。
  可探索用 `Qwen-Image-Edit` 等生成式基座造裂纹/未焊透样本。
- 前置条件：GPU 预算、合成样本的**物理合理性评估**（衰减一致性）、以及合成数据入训的回归
  门禁。在评估通过前不引入合成数据。
- 旁证（调研中发现，更贴合本域）：《J. Manufacturing Processes》Vol 160 (2026) pp 429-441 用
  残差扩散重建 + 多尺度频域注意力做**焊缝 RT 无监督检测**，报告像素级 AUROC 97.80 / AP 93.34。
  同域扩散路线比借用自然图像扩散模型更靠谱，但需 GPU，列入跟踪。

### E. 否决：直接使用 Marigold V2 权重或深度输出

- 模态（自然 RGB vs X 光衰减）与任务（深度 vs 检测）双重不一致；自然图像先验不迁移到射线
  底片。任何"直接用"的设想在此关闭。

### F. 采纳：缺陷密度图辅助任务（`backend/training/density_aux.py`）

把"多 LoRA 单基座多任务"的思路落成一个**与检测互补的稠密回归任务**，服务两个既有痛点：

- **密集气孔群逐个计数（§16 场景 4）**：几十个紧邻气孔会被 NMS 并成一个框。密度图的
  **积分等于缺陷个数**（`mode="integral"`），`count_peaks` 给出逐个读数——这是检测范式做不到的。
- **含噪标注**：框回归对定位误差敏感；密度图 + SinkLoss 只约束块内值集合，对抖动不敏感。

提供：`sigma_for_box`（核宽自适应）、`gaussian_density_map`（peak/integral 双模式）、
`density_integral`、`density_tiles`（→ SinkLoss 的分块视图）、`to_sinkhorn_scale`、
`count_peaks`、`load_yolo_boxes` / `boxes_from_yolo_lines`。仅依赖 numpy（skimage 懒加载）。

**核宽用几何平均而非面积**：`sigma = ratio·sqrt(w·h)`。若用面积，细长裂纹（如 40×2）会得到
与其"薄"方向严重失配的大核，密度图上糊成一片。
**边界裁剪而非补零**：高斯核超出画布的部分被裁掉，不 padding——补零会凭空造出"图外还有缺陷"
的假信号，裁剪只损失边缘信息量、不引入错误方向。

- **验证**：`backend/tests/test_density_aux.py`（29 项）。

## 实证发现（受控实验与踩坑记录）

这一节记录**实测出来的**事实，全部可复现。三条都是"静默失效"类问题——不报错，只是不工作。

### 发现 1：SinkLoss 的**输入量纲契约**（[0,1] 值域下几乎不提供梯度）

传输代价是 `C=(pred_i - gt_j)²`。若输入被压到 [0,1]，平方项被压到 1 以下，而熵正则又给出一份
**与量纲无关的软匹配下限**，结果损失几乎平坦。同一张 64×64 密度图实测（tile=8，eps=0.05）：

| 输入尺度 | 正确预测代价 | 全零预测代价 | 对比度 |
|---|---|---|---|
| 1.0 | 0.0015 | 0.0100 | **6.4 ×** |
| 10.0 | 0.0021 | 0.9971 | **466.5 ×** |
| 100.0 | 0.0014 | 99.7077 | **71945.8 ×** |

→ **必须先把目标缩放到量级 10~100 再送入 SinkLoss**（或同步减小 `eps`）。已提供
`density_aux.to_sinkhorn_scale`，并在 `losses.py` 模块文档与 `test_to_sinkhorn_scale_restores_contrast`
里固化为**回归护栏**（断言不缩放时对比度 < 20、缩放后 > 100）。

### 发现 2：sigmoid 输出头 + 稀疏目标 → **梯度恒零、训练不可恢复地死掉**

实测：模型输出恒 0，**梯度范数恰为 0.000e+00**，损失 300 轮纹丝不动在 5 位小数上。
根因是稀疏目标把优化器推进 sigmoid 饱和区，`sigmoid'(z)` 在 float32 下**下溢到精确 0**，
梯度再也不可能回来。改用 **softplus** 头（无上界饱和、梯度处处非零）后梯度恢复健康。

### 发现 3：稀疏密度图上**裸 MSE 不可训**（最优解就是近零输出）

本 Golden Set 的框**极小**（`sqrt(w·h)` 中位数仅 **1.6px**，min 0.6px），故密度图前景仅约 2%。
实测裸 MSE：loss 从第 15 轮起恒定，**60 epoch 与 300 epoch 的干净测试 MSE 完全相同
（0.077642）**，梯度衰到 7.9e-21 —— 即"多训也没用"，因为它收敛到的是**平凡均值解**，不是局部
极小。**结论：密度图辅助任务必须做前景加权（或等效的重加权）才可训**；这使 `mse_fg` 成为
可训基线，而裸 `mse` 只留作参照。

### 受控实验（`scripts/bench_density_loss_noise.py`）

设计要点（避免把"输入噪声"与"标注噪声"混为一谈）：
- 输入（模拟底片）**始终由干净几何渲染**，噪声**只加在训练标签**上——这才是"标注噪声"；
- 测试集用**干净**标签评估，测的是对真实几何的泛化，而非对噪声的拟合；
- 标签几何取自**项目自有 Golden Set**（`data/eval/golden_v3`，85 张有标注图 / 407 个缺陷），
  不是凭空造的分布；
- 同数据、同种子、同初始化，**只换损失**（`mse` / `mse_fg` / `sinkhorn` / `combo`），
  `combo` 的权重在初始化时自动标定使两项量级相当。

**已得到的确定性结果**（无需训练，精确可复现）：同一批预测下，标签抖动造成的"假惩罚"以
**"一个缺陷都没检出"的损失量级**归一化——

| 核宽设置 | 逐像素 MSE 假惩罚 | tile SinkLoss 假惩罚 | MSE / SinkLoss |
|---|---|---|---|
| 窄核（ratio 0.25, min σ 1.0） | 漏检量级的 **84.84%** | 漏检量级的 **8.82%** | **9.62 ×** |
| 宽核（ratio 1.0, min σ 2.0） | 漏检量级的 **15.94%** | 漏检量级的 **2.33%** | **6.84 ×** |

→ 两种核宽设置下结论一致且同向：**MSE 对标注噪声的假惩罚是 SinkLoss 的约 6.8–9.6 倍**。
这正是 SinkLoss 抗噪的机制性证据（不依赖训练，因此不受随机性干扰）。

**训练端对比：本环境无法给出可信结论，如实记为未完成。** 阻塞项（全部实测）：

| 阻塞 | 实测事实 |
|---|---|
| 无 GPU | venv 内 `torch 2.13.0+cpu`，`cuda=False` |
| 无真实标注 | `data/real_label/labels` 与 `prelabels` **均为空**；仓库内只有合成 Golden Set |
| 任务在当前标签下退化 | 见发现 3：裸 MSE 收敛到平凡解，60 与 300 epoch 结果完全相同 |
| CPU 成本 | 单次 120 epoch 约 2–5 分钟，完整网格（3 噪声档 × 4 损失 × 2 种子）需数小时 |

→ **因此任何"训练时 MSE vs SinkLoss 孰优"的结论，在当前条件下都是不可信的**，本 ADR 拒绝
给出该结论。脚本已内置**塌陷检测**（输出恒零即标记并汇总告警），**拒绝在有塌陷运行时输出可
解读的对比表**——避免后来者被无意义的数字误导。
**复现命令（在 GPU 工作站 + 真实标注就绪后执行）**：
`python scripts/bench_density_loss_noise.py --epochs 300 --seeds 3 --noises clean,mild,heavy --losses mse_fg,sinkhorn,combo`

## 后果

- **正面**：
  - 三个可直接复用的构件（SinkLoss 损失、形状保真指标 + 闭环接入、密度图辅助任务）落到既有
    分层内，零侵入、CI 可验证（新增 4 个测试文件、共 58 项断言）；
  - SinkLoss 抗噪已有**机制性证据**（6.8–9.6×），且量纲契约被固化为回归护栏；
  - X 光域基座路线**已被调研判死一半**（无公开焊缝 RT 基座、朴素 SAM 失败、U-Net 在 IoU 上反超），
    避免了盲目替换骨干的代价；
  - 记录了三类"静默失效"坑（量纲、饱和、稀疏），后续同类工作可直接避开。
- **负面/边界**：
  - **SinkLoss 的实际训练增益仍未量化**（无 GPU / 无真实标注 / 任务在当前标签下退化）。
    当前处于"算法 + 单测 + 机制证据"阶段，**尚未接入任何生产训练跑数**；
  - 形状保真指标是**诊断性**的，不进回归门禁，否则会作废历史基线；
  - 密度图辅助任务在当前（极小框、合成）标签上不可直接用，需前景加权 + 更合理的标签来源。
- 任何"换基座"或"合成数据入训"的动作，须先出调研/评估结论并另立 ADR。

## 备选

- **把 SinkLoss 直接塞进 ultralytics YOLO 损失**：YOLO 内部结构不开放且版本脆弱，破坏
  §19.4 可插拔性（否决）。改为独立可插拔模块，按需在自有训练脚本中调用。
- **把形状保真纳入回归门禁**：会改变门禁口径、历史 `baseline.json` 失效（否决）。先以
  诊断指标落地，累积数据后再议是否升格。
- **为深度任务单独引入 Marigold V2**：本系统无单目深度需求（否决）。
- **直接下载 RAD-DINO 替换 YOLO 骨干**：许可证未决（MSRLA/MIT 冲突）+ 模态为人体胸片 +
  工业缺陷上基座泛化差的独立实证（否决）。改为先做冻结特征线性探测（§C 路径②）。
