# ADR-005：分层依赖铁律 + import-linter 强制

- 状态：Accepted
- 日期：2026-08-04

## 背景
多轮 AI 编程增量开发的最大风险是层间越权（应用层直连 DB、领域层耦合框架），造成接口漂移与技术债务。

## 决策
- 可执行依赖图：**app → infra → domain**（app 依赖领域契约与基础设施能力；infra 实现领域接口；domain 不依赖任何上层）。
- 领域层禁业务 I/O；基础设施层禁业务判定；跨层用 DTO。
- `import-linter` 在 pyproject.toml 定义：
  - layers 契约 `["app", "infra", "domain"]`（任一上层不得依赖下层之外；domain→infra 即违约）；
  - forbidden 契约：`infra` 不得导入 `domain.grade` / `domain.preprocess`（业务判定逻辑）。
  - CI 中 `lint-imports` 失败即阻断（§19.6）。

## 后果
- 正面：层边界机械强制，AI 代码无法越权；契约测试兜底。
- 负面：新增跨层能力须先扩展接口，流程成本略增。

## 备选
- 仅靠文档约定：成本低但无强制力，多次任务后必然漂移，否决。
