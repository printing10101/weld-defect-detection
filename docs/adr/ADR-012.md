# ADR-012：移植 WRT-SAM 频域提示（FPG）到预处理层

- **状态**：已采纳（模块 + 量化验证已交付；"检测器输入扩通道"待 GPU + 真实标注就绪）
- **日期**：2026-09-14
- **关联**：ADR-011（Marigold V2 相关性评估）、`docs/research/xray-foundation-models.md`

---

## 1. 背景与依据

ADR-011 与《X 光域视觉基座调研 memo》给出的三条结论构成本 ADR 的前提：

1. **没有公开的焊缝 RT 域预训练基座**——最对口的 WRT-SAM（arXiv 2502.11338，中国特种设备
   检测研究院，与本系统 §1 承压设备场景同体系）**未开源 checkpoint**；
2. **换基座不是免费升级**——朴素套用 SAM 在焊缝 RT 上 IoU 仅 **1.13**，加 Adapter 才
   **49.25**，而 **U-Net 在 IoU 上反超**（66.72 vs 51.36）；
3. **真正值得移植的是配方**——WRT-SAM 的频域提示生成器（FPG，2D DCT）针对的正是
   "灰度图缺色彩/语义线索"，且**不依赖任何预训练基座**。

因此本轮只移植配方，不动骨干。

## 2. 决策

在 `backend/domain/preprocess/spectral.py` 新增纯算法频域模块，与既有 `pipeline.py`
（预处理算法）、`metrics.py`（质量度量）**同层同风格**：

| 公开 API | 作用 |
|---|---|
| `dct2` / `idct2` | 正交归一化 2D DCT-II 及其精确逆（Parseval 能量守恒） |
| `normalized_radius` | 频点归一化径向频率（跨分辨率可比） |
| `band_edges(n_bands, scheme=)` | 频带边界，支持 `linear` / `log` 两档划分 |
| `radial_band_masks` | 互斥且完备的径向频带掩膜 |
| `band_pass_images` | 逐带重建的空间域频带图（各带求和恰为原图） |
| `band_energy_fractions` | 各频带能量占比（和为 1） |
| `spectral_prompt` | `(K, H, W)` 提示张量，逐带居中归一化到 `[0, 1]` |

**采纳理由**：零新依赖（numpy + scipy 懒加载，与 `metrics.py` 同策略）、无 I/O、不依赖
预训练权重、落在既有预处理域内、符合分层契约（`app -> infra -> domain`）。

## 4. 结论与关键发现

1. **前提条件成立**：频带能量占比的 AUC（0.904–0.920）**略高于**现有拉普拉斯噪声基线
   （0.886），说明它确实承载了现有方法之外的信息，作为额外输入通道有依据。
2. **`log` 划分优于 `linear`**：AUC 更高（0.906–0.920 vs 0.895–0.907），真实底片上高频段
   的动态范围也更大（2.9e-3 vs 2.8e-4，高出约 10 倍）。**真实底片推荐用 `log`**。
3. **但增量有限，是补充而非替代**：真实底片上"高频能量占比"与拉普拉斯噪声估计的
   **相关系数达 0.72–0.74**（中高相关）。因此它在**效应量上并不优于**基线（d=1.15–1.53
   vs 1.719）——两者的判别力有相当重叠。**不应据此废弃既有噪声估计**。
4. **工程可用性**：23–26 MP/s，2448×2048 底片单图 0.19–0.21 s，可支撑**整图级**离线分析；
   但对高吞吐在线检测偏慢，需按 ROI 调用（ROI 尺寸小、开销可忽略）。

### 一处自我更正

冒烟阶段（仅 10 张样本）我曾判断"真实底片高频占比近乎常数（0.0000 ± 0.0000）、特征失去
判别力"。**全量 165 张推翻了该判断**：高频占比实为 2.83e-4 ± 9.12e-4，**变异系数 CV=3.22**——
远非常数，跨图变异显著。原判断由**两个错误叠加**造成：① 10 张样本的偶然偏差；② 报告用
`round(x, 6)` 打印，把 1e-5 量级抹成了 `0.0000`（**当前脚本已改用科学计数法**）。
教训：**小样本冒烟 + 低精度打印**会让结论朝"什么都没有"的方向失真。

## 5. 踩坑记录（均由单测抓出）

1. **提示通道被 DC 压扁**：`spectral_prompt` 初版直接用 `band_pass_images` 归一化，低频带含
   DC（常数分量），实测值域塌成 `[0.84, 1.0]` → 动态范围丧失。修复：**逐带去均值后再归一化**。
2. **`log` 划分在 `n_bands=1` 时边界不到顶**：`np.geomspace(x, top, 1)` **只返回起点**，边界
   停在 `x`，导致 `(x, top]` 的频点无频带覆盖、能量占比之和 < 1（完备性破坏）。修复：`n==1`
   特判。已加回归测试锁定。
3. **Edit 工具静默不落盘（连续 2 次）**：改动 `band_pass_images` / `band_energy_fractions` 时
   工具返回成功但磁盘未变，若不复核会在运行时炸 `TypeError`。**关键改动后必须 `grep` 复核**。

## 6. 明确未做的事

- **未改 `assess_quality` 门禁**：频域指标只作为独立函数提供，不写入 `QualityCfg` 判据，
  以免扰动已标定的 RQI 权重与历史基线。
- **未引入"能量等分"划分**：按能量分位定界会让边界依赖数据、破坏跨图可比性，故只用固定划分。
- **未做检测器输入扩通道实验**：把输入从 1 通道扩成 `1+K` 通道需要重训检测器，而本机
  `torch 2.13.0+cpu`（无 GPU）、`data/real_label/labels` 为空，**不具备重训条件**。
  乱给"提升 X%"的结论即为造假，故不给。

## 7. 后果与后续

fracs = band_energy_fractions(gray, n_bands=4, scheme="log")   # 频域分布诊断
prompt = spectral_prompt(gray, n_bands=4, scheme="log")        # (4, H, W) 提示通道
