## 0. 当前项目真实状态（代码核实）

**已具备（勿重复造轮子）：**
- 检测器 `YoloDetector`：ONNX/torch 双后端、逐类阈值（`class_conf`）、自研 NMS、ONNX 自适应 sigmoid（通道优先布局已修）、人工兜底 —— `backend/domain/detect/yolo_detector.py`
- 不确定性 `estimate_uncertainty`：u_score / u_size / u_class 三信号 max 融合，安全关键类基线 0.6 —— `backend/domain/detect/uncertainty.py`（M4）
- 评级注册表：NB/T47013 已启用、`GB/ASME/ISO` 语义化熔断、`authorized` 熔断 —— `backend/domain/grade/registry.py` + `nb47013.py` 等
- 训练流水线：`real_finetune.py`、`planB_run.py`、`dataset_builder.py`、`augment.py`、`download_swrd.py`/`swrd_converter.py`（SWRD 焊缝数据集）、`steel_tube_ingest.py`、`roboflow_ingest.py` —— `backend/training/`
- 前端：Tauri + Vue3 + Vite + TS（`src/package.json`，含 `build:pkg` 的 Tauri 配置）
- 配置：质量门禁、逐类阈值、批量（`batch.workers/max_per_batch`）、`sync` 端边云适配器占位 —— `backend/configs/default.yaml`
- 模型：`real_synth2/best.pt` → ONNX 11.7MB，6 类（气孔/夹渣/未焊透/未熔合/裂纹/咬边）

**关键缺口（据核实）：**
1. **真实标注仅 144 张**（25 种子已标），远不够泛化（实测 25 张微调完全不泛化）。
2. `ai_prelabel.py` 是**硬编码字典，非真实多模态 VLM 调用**——"AI 预标注"名不副实，仍是人工起点。
3. 检测器为**纯 YOLOv8n 单尺度 640²**，无多尺度融合 / Transformer。
4. 无 INT8 量化 / 边缘部署（ONNX FP32 CPU）。
5. 仅 bbox，**无像素级分割** → 定级定尺寸靠包围盒近似（`mask_refine` 已有掩膜但用于量化，非独立分割头）。
6. 无"缺陷→处置建议"合规建议引擎（仅有评级）。
7. 无标注闭环 / 主动学习（Label Studio 式）。
8. 无联邦。

## 1. 可落地的优化项（借鉴项目 → 代码锚点）

### A. 检测器多尺度 / Transformer 增强
- **借鉴**：LF-YOLO（RMF+EFE）、MFE-IDD（CNN+Transformer）、Yolo-MSAPF（多尺度对齐融合）
- **现状**：YOLOv8n 默认 neck，单尺度。
- **改造点**：
  - 低风险先行：`backend/training/augment.py` 加**多尺度训练 + 多尺度推理 TTA**（不改架构即可提召回）。
  - 中风险：`backend/training/real_finetune.py` + 新增自定义 model yaml，引入多尺度对齐融合 neck；ONNX 导出保持现有通道优先布局兼容。
- **工作量**：中（受 CPU-only 训练慢约束）。**不建议现在上 Transformer 主干替换**（训练成本/风险高）。

### B. 数据量级（头号杠杆）
- **借鉴**：GLASS（ECCV'24 异常合成）、Surface-Defect-Detection（数据集库）、现有 SWRD 接入
- **现状**：144 真实片；`augment.py`、`download_swrd.py`/`swrd_converter.py` 已就绪，但 SWRD 是否实际落地未核实。
- **改造点**：
  - 把 GLASS 式**异常合成**接入合成底片生成器（提升罕见类多样性，尤其裂纹/未熔合）。
  - 落实 `download_swrd.py` 拉取 SWRD 公开焊缝数据做**辅助预训练 / 域适配**。
  - 扩充 `augment.py` 缺陷感知增强。
- **工作量**：中。**这是性价比最高的一项**，直接打你的 #1 缺口。

### C. 罕见类召回（已部分做，需补闭环）
- **借鉴**：MFE-IDD / 逐类低阈值
- **现状**：`configs/default.yaml` 已设 `class_conf` 裂纹 0.05 / 未熔合 0.08 / 未焊透 0.12 低阈值 ✅（已做）。
- **改造点**：在 `backend/training/dataset_builder.py` 加**缺陷感知采样**（罕见类过采样 + 难例挖掘），与 C 项数据合成配合。
- **工作量**：小。

### D. INT8 量化 / 边缘（micronet）
- **借鉴**：micronet（PTQ/INT8/TensorRT）
- **现状**：ONNX FP32 CPU（`yolo_detector._load_onnx` 仅 CPUExecutionProvider）。
- **改造点**：PTQ INT8 量化；**必须复测 score 分布**（已知 legacy ONNX 导出已融合 sigmoid，量化需重标定 `class_conf` 阈值与 `review_conf`）。
- **工作量**：中。**建议先做可行性验证**，确认掉点可控再决定是否纳入部署。

### E. 合规建议引擎（独立适配器，严守双轨纪律）
- **借鉴**：weld-defect-analyzer（缺陷→标准条款映射 / 处置建议）
- **现状**：`nb47013.py` 已输出级别，但**无"验收/返修/复检"处置建议**输出。
- **改造点**：在 `backend/domain/grade/` 下**新增 recommendation 适配器**（不污染 `grade` 主干，符合双轨纪律），把级别 + 缺陷类型 → 处置建议；前端报告页展示。
- **风险**：必须有授权标准文本支撑；当前为非授权过渡态，建议输出带免责声明。
- **工作量**：小–中。**低风险、直接增强产品力**。

### F. 审计 / 批量 / 复核闭环（happyWE14 库表）
- **借鉴**：happyWE14（YOLOv8s+Flask+Spring+MySQL+Vue3）
- **现状**：`default.yaml` 已有 `batch.workers/max_per_batch`；`db_path: data/scan.db`（SQLite）。
- **改造点**：参考其库表设计，在现有 SQLite 上**扩充审计字段**（复核人/复核时间/Cohen's κ 值/批次号/标准版本）；前端加批量进度 + 复核页（已有 `review.kappa_threshold` 配置可用）。
- **工作量**：中。

### G. 标注闭环 / 主动学习（Label Studio 思路）
- **借鉴**：Label Studio（模型辅助标注 + 主动学习）
- **现状**：`ai_prelabel.py` 是**硬编码字典，非真实推理**；`prelabel_user.py`/`promote_seeds.py` 已有种子晋升流程。
- **改造点**（轻量版，先不做重平台）：
  - 把静态字典替换为**模型推理预标**（接 `YoloDetector.infer`）。
  - 用 M4 `estimate_uncertainty` 的 `review_conf` 做**不确定性采样**：高不确定底片优先送人工核对。
  - 与 `promote_seeds.py` 串成"预标→人工核对→晋升训练集"闭环。
- **工作量**：中。**与现有 uncertainty 天然衔接，直接放大标注效率**。

### H. VLM 评片报告 + 像素级分割定级（长线）
- **借鉴**：MMAD（ICLR'25 多模态 LLM）、WPFormer（CVPR'25 像素级分割）
- **现状**：bbox only；无分割头。
- **改造点（长线 v3+）**：WPFormer 式分割支持精确面积/定级（`mask_refine` 已有掩膜基础可复用）；MMAD 式 VLM 生成可解释评片意见。
- **工作量**：大。**不排期，列为长期方向**。

## 3. 风险与纪律提醒
- **勿 fork 低星焊缝项目代码**（普遍弱维护、数据集小、质量参差），只借鉴模块思想。
- **双轨纪律**：竞赛/合规专用逻辑必须做独立适配器，不污染 `domain/grade` 主干（E 项已据此设计）。
- **授权约束**：合规建议（E）须有授权文本；当前非授权过渡态，输出须带免责声明。
- **量化前置**：D 项 INT8 前必须复测 `class_conf`/`review_conf` 阈值，防 score 分布漂移导致漏检。
- **联邦前置**：v3 联邦须先确认客户数据授权边界。
